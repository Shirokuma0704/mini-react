## 1. 무슨 문제였나

브라우저의 실제 DOM 노드 하나를 받아서, 같은 내용을 담은 가벼운 JS 객체(VDOM 노드)로 바꾸는 함수가 필요했어요. 나중에 diff가 이 객체 두 개를 비교하게 돼요.

- 함수: `domToVdom(domNode)` — `src/domToVdom.js`

## 2. 왜 이 방식인가

11-06 오전 명세(`spec-draft.md` 1절)에서 정한 것을 그대로 따랐어요. 따옴표 안은 상철님 말이에요.

- 고른 방식:
    - "종류" 칸으로 글자와 노드를 나눈다 — "C언어에서 타입으로 구분하는 것처럼"
    - 태그 이름, 속성(`class = msg`)을 담는다
    - 안에 든 것들은 "순서대로 목록에 담는다" (처음 아이디어는 `hi_1, b노드_2, bye_3` 처럼 번호 붙이기)
    - 목록 안의 노드도 똑같은 모양이라, 함수가 자기 자신을 다시 불러서(재귀) 안쪽으로 내려가요
- 버린 대안:
    - 번호를 이름에 직접 붙이기(`hi_1`) → 목록의 순서(인덱스)가 같은 일을 자동으로 해 줘서 버림
    - 글자를 노드의 `data` 칸 하나에 넣기 → 글자가 두 군데(`hi`, `bye`)로 나뉘면 칸이 겹쳐서 버림
- 버린 이유: 위 각 줄 오른쪽

AI가 정한 것(명세에 없던 것) — 마음에 안 들면 바꿔요:
- 칸 이름: `kind`, `tag`, `attrs`, `children`, `text`
- 태그 이름은 소문자로 (`<P>`로 써도 `p`)

## 3. 입력 하나 추적

- 입력: `<p class="msg">hi <b>there</b> bye</p>`
- 예상 (오전에 상철님이 명세에 적은 것):
    - 태그 이름 `p`, 속성 `class = msg`
    - 안에 든 것들: 글자 `"hi"` → `b` 노드(안에 글자 `"there"`) → 글자 `"bye"`
- 실제 (테스트 `spec example`에서 나온 값):
    ```
    { kind: 'element', tag: 'p', attrs: { class: 'msg' }, children: [
        { kind: 'text', text: 'hi ' },
        { kind: 'element', tag: 'b', attrs: {}, children: [ { kind: 'text', text: 'there' } ] },
        { kind: 'text', text: ' bye' }
    ] }
    ```
- 거쳐 간 곳: `domToVdom(p)` → 속성 복사 → 자식 3개를 하나씩 `domToVdom`에 다시 넣음 → `b`에서 한 번 더 내려감 → 글자에서 멈춤

예상과 실제를 나란히 보면 한 군데가 달라요. 어디일까요? 이 칸은 상철님이 찾아 주세요 (・ω・)
